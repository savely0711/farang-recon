# Разведка рынка — парсер барахолок Паттайи (Направление 3)

Читает барахолки Паттайи техническим Telegram-аккаунтом и складывает
объявления (ссылка + категория + дата + цена) в Google-таблицу.
Личные данные не собираются. Работает аккуратно: медленное чтение, паузы,
не больше одного нового вступления в группу за запуск.

## Файлы
- `parser.py` — главный скрипт (один запуск = один прогон).
- `login.py` — разовый вход аккаунтом, выдаёт строку сессии.
- `channels.py` — список каналов (старт: топ-3 лидера).
- `categories.py` — категории для ИИ (наши 10 + разведочные).
- `classify.py` — ИИ-разбор поста (объявление? категория? цена?).
- `sheets.py` — запись в Google-таблицу (POST в Apps Script Web App).
- `state.py` — память «докуда дочитали» (`state.json`).
- `.env` — секреты и настройки (НЕ в git).

## Установка на сервер (Ubuntu, кратко)
```bash
sudo apt update && sudo apt install -y python3-pip git
git clone <репозиторий> recon && cd recon      # или скопировать файлы
pip3 install -r requirements.txt
cp .env.example .env                            # затем заполнить .env
```

### Что нужно заполнить в `.env`
1. `TG_API_ID` / `TG_API_HASH` — один раз на https://my.telegram.org → API development tools.
2. `ANTHROPIC_API_KEY` — ключ ИИ (тот же, что на сайте).
3. `SHEET_WEBHOOK_URL` / `SHEET_TOKEN` — запись в таблицу через Apps Script Web App.
   К таблице привязан скрипт-приёмник (`apps_script.gs`), развёрнутый как Web App;
   URL вида `https://script.google.com/macros/s/.../exec` кладём в `SHEET_WEBHOOK_URL`,
   а общий пароль-токен (та же строка, что вшита в скрипт) — в `SHEET_TOKEN`.
   Пока `SHEET_WEBHOOK_URL` пуст — парсер работает в тестовом режиме (в таблицу не пишет).
4. `TG_SESSION` — получить так:
   ```bash
   python3 login.py      # ввести номер → код из Telegram → пароль (если есть)
   ```
   Скрипт напечатает строку сессии — вставить её в `.env`.

## Запуск вручную
```bash
python3 parser.py
```

## Ежедневное расписание (cron)
```bash
crontab -e
# каждый день в 09:00 по времени сервера:
0 9 * * * cd /root/recon && /usr/bin/python3 parser.py >> recon.log 2>&1
```

## «Первое касание» — авто-отправка авторам (пункт 14, `outreach.py`)

Отдельная программа рядом с парсером. Разведка при каждом новом объявлении с
ником автора кладёт его в очередь `outreach_queue.jsonl`; `outreach.py` берёт
из очереди и пишет автору **один раз**: «Здравствуйте! Ваше объявление ещё
актуально? <ссылка>». Дальше диалог ведёт Савелий сам, как человек.

Источник правды «кому уже писали» — колонка **«Написали?»** в таблице-CRM:
`Да` (написали), `Нет` (в очереди), **`Премиум`** (человек принимает письма
только от Telegram Premium — бот его НЕ трогает, пишет Савелий вручную; строка
жёлтая), **`Не доставлено`** (личка закрыта, ник исчез; строка серая). Бот берёт
в работу только `Нет`, а после отправки/отказа сам проставляет нужный статус.

Гарантии и щадящий режим:
- один автор = одно сообщение навсегда (вечный список `contacted.json`);
- отказ не «подвешивает» очередь: за запуск пробуем до `OUTREACH_MAX_ATTEMPTS`
  (5) авторов подряд, пока одно письмо не уйдёт; временные сбои — до
  `OUTREACH_FAIL_LIMIT` (3) попыток, потом «Не доставлено»;
- пишем только по объявлениям старше суток (`OUTREACH_MIN_AGE_HOURS`);
- с 2–3 личных аккаунтов по очереди; у каждого дневной лимит с прогревом
  (`OUTREACH_DAILY_START`→`OUTREACH_DAILY_MAX`, шаг `OUTREACH_WARMUP_STEP`);
- только «человеческие» часы по Бангкоку (`OUTREACH_HOURS`) + случайные паузы;
- **темп**: между двумя письмами одного аккаунта — минимум `OUTREACH_MIN_GAP_MIN`
  (25) минут плюс случайная добавка до `OUTREACH_GAP_JITTER_MIN` (10) минут.
  Правило живёт в файле состояния самого бота, поэтому его не сломает ни сбитое
  расписание cron, ни `OUTREACH_PER_RUN` больше единицы;
- если Telegram ограничил аккаунт (FloodWait/PeerFlood) — аккаунт уходит на
  паузу: первая блокировка 6 ч, вторая **подряд** сутки, третья и дальше трое
  суток (`OUTREACH_PEERFLOOD_STEPS`). «Подряд» = новая блокировка случилась в
  течение `OUTREACH_PEERFLOOD_RESET_HOURS` (24) часов после окончания прошлой
  паузы. Ушло письмо или сутки прошли спокойно — счёт заново с 6 часов;
- по умолчанию ВЫКЛЮЧЕНО (`OUTREACH_ENABLED=1` включает).

### Что смотреть, если что-то не так
```bash
cd /root/recon && python3 diag.py     # один отчёт: расписание, настройки,
                                      # состояние аккаунтов, письма за сегодня
                                      # с интервалами, хвост журнала
python3 resume.py                     # предпросмотр пересчёта зависшей паузы
python3 resume.py yes                 # применить (или resume.py now — снять совсем)
```

### Настройка
1. Для КАЖДОГО отправляющего аккаунта — вход одной командой (сессия сама ляжет
   в первый свободный слот `TG_SEND_SESSION_1..5` в `.env`):
   ```bash
   python3 loginsend.py   # номер (можно просто цифрами) → код из Telegram → пароль 2FA
   ```
   Запускать по разу на каждый аккаунт. Читающий аккаунт разведки `TG_SESSION` —
   отдельный, его не трогаем. Новый аккаунт стартует с прогрева
   (`OUTREACH_DAILY_START`), темп у каждого аккаунта считается отдельно.
2. Проверить план БЕЗ отправки (никому не пишет, только показывает, кому бы написал):
   ```bash
   OUTREACH_DRY=1 python3 outreach.py
   ```
3. Включить в `.env`: `OUTREACH_ENABLED=1` (или `python3 sendon.py`).
4. Разовый прогон прямо сейчас, мимо ограничения по часам: `python3 sendnow.py`.

### Расписание (cron) — мелкими частыми запусками

```bash
crontab -e

*/25 * * * * cd /root/recon && /usr/bin/python3 outreach.py >> outreach.log 2>&1
```
